# 测评转化插入页设计稿

这个目录用于保存不接入业务代码的前端体验设计稿，目标是把现有功能型测评包装成更有吸引力的消费级 funnel。

## 文件

- `index.html`：静态 HTML 原型，可直接用浏览器打开。
- `screenshots/overview.png`：全部页面总览。
- `screenshots/*.png`：单页移动端预览截图。

## 建议插入点

| 页面 | 插入位置 | 作用 | 数据 |
| --- | --- | --- | --- |
| 同龄用户证明 | 年龄或基础信息后 | 降低陌生感，建立“很多人也在做” | 无业务答案，记录曝光事件即可 |
| 目标确认反馈 | 主目标后 | 让用户感觉系统理解了目标 | 可读取 `goal` 生成文案 |
| 每天 10-20 分钟承诺 | 运动频率前后 | 降低时间成本疑虑 | 无业务答案 |
| 专家背书 | 生活/饮食题前 | 建立专业可信度 | 无业务答案 |
| 分析加载 | 必填数据完成后 | 合理化等待，强化“正在生成” | 记录加载曝光和完成事件 |
| BMI 预览 | 服务端计算后 | 免费价值展示，制造继续动机 | 读取服务端 BMI/画像结果 |
| 重要事件 | BMI 预览后 | 强化目标动机 | 可选答案：事件类型、事件日期 |
| 目标预测图 | 事件后或结果页前 | 让用户看到未来状态 | 读取服务端预测曲线 |
| 计划生成与评价 | 付费前 | 提高信任，铺垫解锁 | 无业务答案，记录曝光 |
| 邮箱隐私页 | 付费页前 | lead capture，承诺隐私 | 邮箱，建议单独 lead 表 |
| 订阅前报价页 | checkout 前 | 展示价格、保障、权益 | offerId、价格、折扣、币种 |

## 设计原则

1. 单选题自动推进，多选题保留明确的下一步按钮。
2. 每 3-5 个问题插入一个非答题页，避免用户觉得只是在填表。
3. 文案使用用户目标语言，不暴露数据库字段语言。
4. 所有健康计算和预测仍以服务端结果为准，前端只展示。
5. 信任内容分散在付费前逐步出现，不集中堆在支付页。
